# CampusLife: 3-Hour Vibe Coding Plan

## Goal

Build a polished, mobile-friendly CampusLife prototype in 3 hours. Focus on three dashboards, sample data, and a few real interactions instead of trying to build every feature.

## 1. The Three Dashboards

### Campus Feed

**Difficulty:** Easy

- University announcements with source links
- Student posts in a simple social feed
- Lost & Found posts with photos
- A working like or confirm button

**Estimated time:** 35 minutes

### Student Hub

**Difficulty:** Easy

- Useful university links
- First-year student checklist
- Student discounts and affordable food
- Exam calendar with sample dates
- Internships and hackathons

**Estimated time:** 35 minutes

### Student Community

**Difficulty:** Medium

- Study groups and upcoming sessions
- Course notes directory
- Housing and roommate listing cards
- Simple activity points counter

**Estimated time:** 35 minutes

Keep content as sample data unless a feature truly needs to be live. Prioritize a clear, working demo.

## 2. Three-Hour Schedule

### 0:00–0:20 | Set up the app

Create the project, navigation, shared layout, and mobile-friendly design.

### 0:20–1:15 | Build the dashboards

Use prepared sample data. Prioritize the Campus Feed and Student Hub.

### 1:15–2:00 | Add working interactions

Make buttons, filters, checklist progress, likes, and study-session joins work.

### 2:00–2:30 | Polish the experience

Add realistic content, icons, empty states, and consistent styling.

### 2:30–3:00 | Test and deploy

Fix broken screens and links, test on mobile, and get a shareable URL.

## 3. Leave These Features for Later

- Live university website crawling
- Real-time chat like Discord
- Login with student verification
- Real discount redemption with partners
- Automatic exam calendar collection
- Carpool matching
- Anonymous support forums
- AR navigation and voice assistant

These features need more time for backend development, integrations, privacy, safety, or testing. Show them as future plans instead of risking the core demo.

## 4. Definition of a Successful MVP

- Three dashboards with clear navigation
- Campus announcements with source links
- Student posts and Lost & Found sample content
- Useful university resources and student benefits
- Study sessions and a first-year checklist
- A polished mobile layout deployed to a live URL

**Rule of thumb:** A few genuinely working interactions are better than 20 buttons that do nothing.

## Final Advice

Use sample data for anything that does not need to be live. Make a small number of interactions genuinely work. Build one coherent campus information app first, then present live crawling, real-time chat, student verification, and other advanced features as the roadmap.
